# 실제 선수 데이터와 인형 비교 (BoxingVI)

인형의 펀치 동작 수치(`lib/pose/poses.dart`의 `animSeconds`, `_impactAt`, 자세 값)는
[BoxingVI](https://github.com/Bikudebug/BoxingVI) 데이터셋의 실제 선수 펀치와 같은 지표로 비교해 맞췄다.
데이터는 앱에 들어가지 않고, 수치를 맞추는 기준으로만 쓴다.

데이터셋에는 라이선스가 명시돼 있지 않다. 그래서 저장소에 포함하지 않고, 필요할 때 각자 받는다.

## 다시 돌리기

```bash
# 1. 데이터 받기 (관절 좌표·주석만, 약 50MB). 프로젝트 밖 별도 폴더에.
python -m venv .venv && .venv/Scripts/pip install gdown openpyxl numpy
.venv/Scripts/python -m gdown --folder https://drive.google.com/drive/folders/1Vyl8twJQ1qkqEPwhvfsrJsJ8nLQ92uoy -O <데이터 폴더>

# 2. 인형 동작 내보내기
EXPORT_PATH=<작업 폴더>/model_punches.json flutter test tool/export_model_test.dart

# 3. 비교 (같은 폴더에 comparison.json도 생성)
.venv/Scripts/python -I tool/boxingvi/compare.py <데이터 폴더> <작업 폴더>/model_punches.json

# 4. 자세·순서 추가 분석
.venv/Scripts/python -I tool/boxingvi/guard.py tool/boxingvi <데이터 폴더> <작업 폴더>/model_punches.json     # 안 치는 손, 턱-어깨 간격
.venv/Scripts/python -I tool/boxingvi/guardpos.py tool/boxingvi <데이터 폴더> <작업 폴더>/model_punches.json  # 가드 손목·팔꿈치 높이
.venv/Scripts/python -I tool/boxingvi/onset.py tool/boxingvi <데이터 폴더> [model_punches.json]   # 칠 때 부위별 출발 순서
.venv/Scripts/python -I tool/boxingvi/retract.py tool/boxingvi <데이터 폴더> [model_punches.json] # 거둘 때 순서
```

## 방법

- **데이터:** 영상 9편(V6은 프레임 단위 데이터라 클립 경계가 불확실해서 제외)에서 펀치 4,743개를 썼다. 형식은 AlphaPose 2D 관절(COCO 17점), 30fps.
- **인형:** 3D 관절을 7개 카메라 각도(-90°~90°)에서 2D로 투영한 뒤 같은 지표로 측정했다.
- **지표 단위:** 길이는 몸통 길이(어깨 중앙~골반 중앙) 단위다. 카메라 거리와 선수 체격이 달라도 비교할 수 있게 하려는 것이다.
- **스탠스:** 영상마다 잽을 치는 손으로 오소독스/사우스포를 판정했다.
- **임팩트 시점:** 어깨~주먹 거리가 가장 먼 순간으로 잡았다. 어퍼컷은 주먹이 가장 높은 순간으로 잡았다.

### 조정 전과 달라진 점
- **시간:** 펀치가 1.5~2배 느렸다. 지금은 실제 속도에 맞췄다.
- **스텝:** 잽 스텝이 16cm였다. 실제는 대부분 몇 cm를 밀고 들어가고, 크게 내딛는 잽은 12%뿐이다.
- **피벗:** 크로스와 훅의 피벗·뒤꿈치 들기가 실제의 3배였다.
- **어퍼 준비:** 어퍼 준비 동작에서 너무 주저앉았다.
- **주먹 높이:** 스트레이트와 훅이 출발보다 내려가며 들어갔다. 실제는 약간 올라간다.

### 2차 조정 (자세·순서·궤적)
- **턱과 어깨:** 실제 선수는 코가 어깨선보다 몸통 길이의 0.08~0.26배 위에 있다(턱을 당기고 어깨를 올림). 인형은 0.45배로 목을 세우고 있었다. 지금은 0.19~0.21.
- **가드 손:** 실제 가드 손목은 코보다 0.43배 아래(턱~목 높이)다. 인형 주먹은 코 높이였다. 머리를 낮추고 주먹을 턱 높이로 내렸다. 그만큼 펀치 목표 높이도 내려서 주먹 상승을 실제에 맞췄다.
- **칠 때 순서:** 모든 펀치에서 발·골반·어깨가 손목보다 먼저 출발한다. 50% 지점 기준 손목이 어깨보다 18~37ms 늦다. 골반과 어깨는 거의 동시다(리드 훅만 골반이 5~11ms 먼저). 펀치 수백 개를 프레임 사이 보간으로 모아 잰 값이고, 부트스트랩 95% 구간이 모두 0을 포함하지 않는다. 인형은 팔이 구간의 20% 늦게 출발한다(10~28ms).
- **거둘 때 순서:** 손목이 몸보다 15~35ms 먼저 돌아온다. 인형도 팔이 먼저 돌아온다. 손목 50% 복귀 시간은 실제 54~80ms, 인형 53~89ms다.
- **훅 궤적:** 휨이 실제 0.10~0.16, 인형 0.42~0.55였다. 준비 동작에서 주먹을 옆으로 크게 빼던 것을 줄였다. 지금은 0.13.

### 3차 조정 (속도 곡선·준비 동작)
- **속도 곡선:** 실제 몸(어깨·골반)은 임팩트까지 시간의 약 13% 지점에서 20%, 35% 지점에서 50%를 움직인다. 초반에 몰아서 돈다. 손목은 비교적 고르게 나간다. 인형도 몸은 구간 70% 안에 회전을 마치고, 팔은 거의 바로 출발하게 바꿨다. 잽·크로스 어깨 50% 시점은 실제 38~45ms, 인형 약 42ms(동작 시간 차이 환산)다.
- **준비 동작:** 훅·어퍼를 치기 전에 뒤로 감는 동작이 실제에는 거의 없다. 손목 20% 시점이 실제 27~58ms인데, 준비 동작이 있던 인형은 70~97ms였다. 준비 동작을 없애고, 대신 가는 도중 훅은 바깥으로, 어퍼는 앞으로 나가며 올라가게 했다. 지금은 26~52ms이고 휨은 리어 훅 0.13, 어퍼 0.24~0.33이다. 리드 훅 2D 휨은 중간 지점에서 팔이 가장 펴져 임팩트를 잘못 잡으므로, 3D 궤적으로 따로 확인했다(휨 0.1 이상, `test/pose_test.dart`).

## 한계
- **회전 순서:** 클립 하나로는 30fps 프레임보다 짧은 차이를 볼 수 없다. 위 순서는 수백 개를 모은 통계다.
- **궤적 휨:** 2D 투영과 카메라 각도 영향이 크다. 훅은 "가장 멀리 뻗은 순간"이 임팩트를 정확히 잡지 못한다. 실제 25~75% 범위에 드는지만 맞췄다.
- **임팩트 높이 절댓값:** 카메라 높이를 몰라서 쓰지 않고, 가드 대비 상승량만 맞췄다.
- **빠진 동작:** 데이터에 방어 동작과 바디샷이 없다. 방어 동작과 바디샷은 코치 시범 영상으로 따로 맞췄다(`tool/video_pose`).
