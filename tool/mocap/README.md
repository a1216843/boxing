# 모션캡처로 펀치 움직임 맞추기

[CMU Graphics Lab Motion Capture Database](http://mocap.cs.cmu.edu/search.php?maincat=4&subcat=8)의 복싱 클립 7개
(13_17, 13_18, 14_01~03, 15_13, 17_10)를 쓴다. 적외선 카메라 12대, 120fps로 찍은 관절 회전값이라 영상에서 추정한
포즈(MediaPipe)와 달리 깊이 오차가 없다. 이용 조건은 FAQ의 "The motion capture data may be copied, modified, or
redistributed without permission."이다. 원본 파일은 저장소에 넣지 않는다.

## 자세는 정석, 움직임은 실제 사람

피험자가 복싱 선수가 아니라 연구실 참가자라 자세가 엉성하다.

- 스탠스가 넓다 (발 간격 0.7~0.95m). 코치 영상 가드 비율로는 약 0.5m.
- 같은 사람이 클립 중간에 오소독스·사우스포를 바꾼다.
- 손목이 빠르게 움직인 209번 중 80번은 팔을 떨어뜨리는 등 펀치가 아니었다. 어퍼컷은 없었다.

그래서 관절 위치를 그대로 재생하지 않고 움직임의 결만 가져온다. 자세(가드, 임팩트 모양)는 코치 영상과
BoxingVI로 맞춘 키 자세(`lib/pose/poses.dart`)를 쓰고, 그 사이를 가는 방식(가속·감속, 부위별 순서, 몸의 오르내림)은
모션캡처 곡선을 따른다 (`WarpedMove`). 한 펀치가 아니라 같은 종류 펀치 여러 개의 시간 정규화 곡선 중앙값이라
한 사람의 버릇은 묻힌다. 재생 시간은 BoxingVI 값을 그대로 둔다 (피험자의 복귀가 0.37~0.51초로 실제 선수보다 느리다).

## 다시 돌리기

```bash
# 받기 (각 subject의 .asf와 해당 trial의 .amc, 프로젝트 밖 폴더에)
curl -O http://mocap.cs.cmu.edu/subjects/14/14.asf -O http://mocap.cs.cmu.edu/subjects/14/14_01.amc  # ...
.venv/Scripts/python -I tool/mocap/export.py <asf/amc 폴더> lib/pose/mocap_data.dart
.venv/Scripts/python -I tool/mocap/bounce.py <asf/amc 폴더>
```

## 결과

펀치 검출은 손목 속도 봉우리(3m/s 이상), 분류는 임팩트 때 팔꿈치 각도(스트레이트 150° 이상, 훅 130° 미만이고
팔꿈치가 어깨 높이 근처)로 했다.

| 곡선 | 펀치 수 | 출발→임팩트 중간의 진행도 (주먹 / 골반 / 어깨) |
|---|---|---|
| 잽 | 16 | 0.42 / 0.57 / 0.55 |
| 크로스 | 14 | 0.43 / 0.84 / 0.52 |
| 훅 (리드·리어) | 7 | 0.44 / (표본 부족, 어깨로 대신) / 0.69 |

주먹이 절반쯤 왔을 때 몸은 이미 절반 넘게 돌아 있다. BoxingVI에서 본 "몸이 먼저, 주먹이 뒤따라" 순서와 같다.
데이터에 없는 펀치는 팔 모양이 비슷한 곡선을 빌린다: 바디 스트레이트 ← 같은 손 스트레이트, 어퍼컷·바디 훅 ← 훅.

가드 바운스 (`bounce.py`): 두 손목이 1.5m/s 미만으로 1초 넘게 이어진 51구간에서 골반 높이를 쟀다.

| | 실제 | 조정 전 인형 | 지금 인형 |
|---|---|---|---|
| 주기 | 2.4Hz (사분위 2.1~2.6) | 1.6Hz | 2.4Hz |
| 크기 (봉우리-골 절반, 앱 단위) | 0.044 (사분위 0.033~0.052) | 0.01 | 0.033 (피험자가 깡충거리는 편이라 사분위 하단) |

## 한계

- 연구실 참가자 4명의 섀도복싱이다. 훅 표본이 7개뿐이고, 골반 회전이 6° 넘는 펀치가 적어 골반 곡선은 잽 외에는 표본이 작다.
- 방어 동작은 데이터에 없어 곡선을 쓰지 않는다.
